## 2. 产品目标

建设一套面向非技术领导汇报的城市信控智能体前端演示系统，通过连续的地图动作讲清楚：

1. 系统如何主动扫描并发现交通问题；
2. 智能体如何定位路口、读取设备、认知渠化、核验指标并完成流量溯源；
3. 系统每天采取了哪些动作、取得了什么效果、如何通过人机协同保障安全，以及如何沉淀经验。

系统采用纯前端实现，业务数据通过 `data/` 下的 JSON/GeoJSON 文件读取；渠化数据来自 PostgreSQL 只读查询后的真实路网快照，不再使用手工模拟十字路口，为后续后端接口替换保留统一数据访问层。

## 3. 总体设计

### 3.1 产品形态

采用单页连续地图叙事，不将 Act 1、Act 2、Act 6 制作成互不相关的独立页面。

- Act 1 与 Act 2 共用同一高德地图实例，保持镜头和图层连续。
- 地图固定采用垂直 2D 俯视视角，不使用 2.5D 透视。
- 监测点、问题标记、设备、渠化、拓扑、溯源链路全部使用高德地图原生地理覆盖物；禁止使用屏幕百分比定位业务图形。
- Act 6 切换为 AI 日报布局，同时保留弱化地图作为空间背景。
- 顶部幕次导航支持手动跳转，自动演示按 Act 1 → Act 2 → Act 6 播放。
- 所有镜头、图层和面板由统一叙事状态机驱动，支持暂停、继续、跳步和重新播放。

### 3.2 叙事链路

```text
区域扫描
→ 异常发现与 10 秒待处理
→ 路口定位
→ 设备感知
→ 渠化认知
→ 道路拓扑
→ 指标证据
→ 多模态核验
→ 问题确认
→ 下游/对向验证
→ 流量溯源
→ AI 日报与经验沉淀
```

### 3.3 视觉风格

定位为“政务汇报 + 城市运行指挥”，不沿用普通后台或游戏化大屏风格。

- 地图：高德白色底图，压低无关 POI 的视觉权重。
- 主色：深海军蓝，用于标题、框架和正式感。
- 智能色：青绿色，用于监控、智能体运行和正常链路。
- 预警色：琥珀橙，用于异常、排队风险和倒计时。
- 危险色：红色，仅用于明确异常或指定设备类型。
- 面板：Act 1 / Act 2 使用 Agent Loop 深色分析坞、直角细边框、局部青色高能线和密集信息层级；Act 6 使用浅色复盘工作台。
- 动效：平滑、克制、有因果关系；避免全屏粒子、强频闪和无意义装饰。
- 主要适配：1920×1080；兼容 1366×768。

V3 视觉系统严格提取两个参考项目的设计令牌并按场景分工：

- Act 1 / Act 2 地图叙事：采用 `agent-loop-project` 的深夜蓝 HUD、青色运行态、暖黄主证据、双层发光线和半透明分析坞。
- Act 6 复盘与人机协同：采用 `references/static/agent-workbench.html`、`human-in-loop.html` 的浅蓝页面底、纯白卡片、蓝色主操作、青绿成功态和橙红风险态。
- 禁止再次混用灰绿色、低对比玻璃面板和无明确语义的装饰色。

### 3.4 全局布局

- 顶部：系统名称、幕次导航、智能体运行状态、当前时间。
- 左侧：异常列表、目标对象、结构化诊断结论。

## 4. Act 1 设计

### 4.1 被动扫描

1. 初始展示解放东路与奥体西路周边区域。
2. 被监控路口以青绿色呼吸点展示。
3. 扫描光带严格复用 `agent-loop-project/src/mesh/cityScan.js` 的视觉逻辑：透明青色边缘、白色高能核心、加法发光观感，3.2 秒从西向东扫过路网包围盒并循环。
4. 约 10 秒后，目标路口出现绑定经纬度的地图图钉，使用紧凑的异常图标和就近信息标签，不使用长引线气球。
5. 右侧扫描坞切换为异常事件坞，展示路口、问题类型、触发指标和严重程度；左侧城市运行态势坞保持稳定。
6. 异常卡片底部显示 10 秒自动处理倒计时。
7. 用户点击“立即研判”可提前进入 Act 2；无操作则自动进入。

### 4.2 主动提交

- 底部常驻自然语言输入框和发送按钮。
- 输入提交后终止被动扫描计时，依次展示对象解析、路口匹配和诊断任务生成。
- 主动与被动两种模式最终进入同一套 Act 2 状态机。

## 5. Act 2 设计

建议完整演示时长 60–80 秒，各阶段时长在 JSON 中配置。

### 5.1 路口定位

- 从区域视角连续飞向解放东路与奥体西路交叉口。
- 先移动到目标路口，再逐步降低高度和缩小范围。
- 到达后目标环脉冲一次，作为定位完成的视觉签字。

### 5.2 设备感知

- 电警、地磁、卡口、信号机等设备按类型依次显现。
- 图例展示颜色、设备类型、在线数量和覆盖率。
- 点位悬停可查看设备名称、状态和关联车道。
- 本版本采用“绿色代表电警、红色代表地磁”的映射；其他设备使用蓝色和金色。

### 5.3 渠化认知

- 设备层渐隐，镜头继续下钻。
- 绘制路口四个进口方向、车道边界、停止线、斑马线和转向箭头。
- 问题进口道使用轻量橙色描边，不提前展示诊断结论。

V4 渠化特效按参考项目 `channelizationLayer.js v3` 的数据组织、坐标约定和构造顺序实现：

1. 先绘制四条深灰路臂与中心路面；
2. 再绘制中性灰白路缘、黄色中心分隔线和白色曲线角点；
3. 车道虚线使用灰白虚线；
4. 每个进口绘制两条红色细停车线；
5. 车道转向使用放大的实心白色方向符号并靠近停车线；
6. 指标阶段按 `round(queueM / 8)` 生成车辆序列，按车道功能形成不同队列长度；
7. 饱和度大于 85% 使用红色车辆，其他进口使用绿色低饱和度车辆作对照；
8. 路面、标线、方向符号、道路名和车辆按节拍依次进入。
9. 严格遵循“进口位于路臂局部 +X、出口位于 -X”的坐标约定，并使用参考实现 `armToWorld` 的符号规则转换到高德经纬度。
10. 箭头由真实 `lane_func_code` 生成，`A/B=左转`、`C=直行`、`D/E=右转`，`F/G/L/R/T` 为辅助码，`Z` 无直行码时按直行归一化。
11. 停止线与转向箭头只画在入口侧，出口侧仅呈现真实路面、路缘和车道虚线。

所有对象均为高德经纬度覆盖物，禁止使用屏幕坐标模拟路口。

### 5.4 道路拓扑

- 镜头略微抬升，渠化信息降透明度。
- 突出南北向与东西向道路，展示道路名称。
- 显示上游、目标口、下游节点及方向箭头。

### 5.5 指标抽屉

依次展示：

- 流量；
- 饱和度；
- 排队长度；
- 绿灯利用率。

排队长度为本次问题的主证据，使用橙色证据框，并显示动态阈值、实际值和超限比例。

### 5.6 多模态核验

- 展示现场视频抽帧、设备来源和采集时间。
- 支持点击放大。
- 将图像证据与指标证据关联展示。

### 5.7 问题确认与拓扑验证

- 地图出现唯一结论锚点“排队异常成立”。
- 同屏比较目标进口、对向车道和下游承接能力。
- 下游有余量使用蓝绿色；目标进口异常使用橙色。

### 5.8 流量溯源

- 数据结构对齐参考项目的“目标节点 + 主走廊逐跳链 + 汇入支路 + 上下文链路”模型，禁止将溯源简化为三条飞线。
- 当前演示包含 13 个拓扑节点、12 条关联链路、六跳主走廊与五条汇入支路。
- 从目标路口按拓扑向上游逐跳展开，高德 `Polyline` 使用 `showDir` 表达流向。
- 线宽表达贡献度；主链节点显示“第 N 跳、单跳贡献、累计解释率”，支路保留拓扑与悬停信息，避免标签堆叠。
- 主走廊六跳累计解释 92.0% 的到达流量，并说明支路在第二至第五跳的汇入关系。

V3 进一步对齐参考项目 `flowTraceCorridorLayer.js`：

- 仅渲染目标节点、主走廊节点、拓扑锚点以及覆盖率不低于 10% 的支路节点；
- 支路只能使用真实 `link.path`，采用弱蓝色双层线，不挂方向箭头；
- 主走廊按相邻节点圆心连接，采用 `#F5A623` 发光外层和 `#FFCF7A` 核心层；
- 线宽采用 `2.8 + sqrt(coverage / 100) × 5.7`；
- 目标节点为绿色，主走廊节点为暖黄，支路节点为蓝色；
- 仅目标与主链挂文字标签，避免支路标签遮挡；
- 主链同时使用高德 `showDir` 静态方向纹理与多组持续移动的方向粒子；
- 从目标口开始按第 1 至第 6 跳逐段展开。

### 5.9 面向领导的专家分析链（V5 补充）

领导视角不应只看到“查到了哪些指标”，而应看到智能体如何像交通专家一样提出问题、排除原因、比较方案并控制副作用。Act 2 的主叙事因此调整为：

```text
路口认知
→ 方向拆解
→ 异常核验
→ 溢流判因
→ 约束检查
→ 方案生成
→ 反事实推演
→ 专家决策
→ 源头治理
```

每一步必须持续呈现四类信息：

1. 当前要回答的问题；
2. 智能体观察到的证据；
3. 基于证据形成的判断；
4. 下一步需要继续验证的事项。

空间分析固定采用四个角色，避免“目标进口排队多，所以直接加绿”的单点逻辑：

| 空间角色 | 本例对象 | 必须回答的问题 |
|---|---|---|
| 分析方向 | 北进口向南直行 | 排队是否持续增长，当前有效放行是否不足？ |
| 垂直冲突方向 | 解放东路东西向 | 北进口增加绿灯后，东西向等待是否会越过警戒线？ |
| 下游承接 | 南侧坤顺路方向 | 新增放行是否会推高下游占有率并形成二次回溢？ |
| 上游来车 | 轻风路—工业南路 | 连续到达波是否是放大因素，能否通过小比例截流削峰？ |

#### 本例诊断结论

- 北进口排队 129m，超过 114.8m 动态阈值，连续 3 个周期增长，异常成立；
- 下游占有率 42%，仍有约 168m 储车空间，因此排除“下游阻塞导致溢流”；
- 北进口饱和度 0.89、绿灯利用率 54.2%，有效放行不足是直接原因；
- 上游前两跳贡献 57.9%，连续到达波是放大因素；
- 东西向当前排队 63m、警戒线 92m，只能让渡约 4 秒绿灯。

#### 反事实方案比较

| 方案 | 北进口结果 | 东西向结果 | 下游结果 | 判断 |
|---|---:|---:|---:|---|
| 不干预 | 129m 并继续增长 | 63m | 42% | 溢流风险高 |
| 北进口单点 +8s | 88m | 101m | 61% | 将压力转移到垂直方向，不采用 |
| 目标 +4s、上游削峰 12%、下游绿波协调 | 78m | 71m | 55% | 三处均在安全边界内，推荐 |

最终建议不是简单加绿，而是“适度加放 + 上游削峰 + 下游协调”的组合策略，并绑定三个自动回退条件：

- 东西向排队超过 92m，立即回退 2 秒；
- 下游占有率超过 65%，停止北进口加放；
- 上游排队超过 30m，降低截流比例。

#### 数据口径

- 路口中心、进出口、车道数、车道功能码和路网拓扑：使用 `road6`、`version_id=20260501` 的真实数据库快照；
- 排队、饱和度、方向状态和方案效果：本阶段使用 `frontend/public/data/act2/expert-diagnosis.json` 演示数据；
- 页面中必须明确标注“真实路网快照 + 演示诊断数据 + 演示反事实推演”，避免把 Mock 结果误解为线上控制结论。

## 6. Act 6 设计

页面采用“AI 交通运行日报”形式，包含：

1. 今日总览：扫描次数、发现问题数、生成方案数、自动执行数、平均响应时长、闭环完成率。
2. 治理效果：排队长度、平均延误、通行效率、绿灯利用率的前后变化。
3. 动作分布：自动执行、待审批、参数微调、人工接管、驳回、恢复自动控制。
4. 人机协同：除展示时间线外，提供可操作工作台，完成 AI 建议 → 专家输入 → 参数留痕 → 效果追踪。
5. 经验沉淀：提供场景认知、问题诊断、控制策略、管控经验四维输入，支持模板带入、保存草稿和发布经验。

人机协同必须具备以下实际输入入口：

- 待审批：查看当前值、建议值、风险边界，输入审批意见后批准或驳回；
- 参数微调：编辑建议参数并填写调整依据；
- 人工接管：填写接管原因、现场指令与恢复条件；
- 经验录入：从参考模板带入四维经验，允许人工修订并保存或发布。

所有操作在纯前端演示模式下写入 `localStorage`，同时即时追加到安全留痕时间线；接入后端后保持相同交互契约。

人机协同状态采用：

```text
自动执行
待人工审批
参数微调
人工接管
驳回
恢复自动控制
效果验证
经验沉淀
```

```text
nodes[]                 # 目标、主走廊、支路、下游节点
links[]                 # main / branch / context 链路及真实路径
mainCorridorChain[]     # hop、单跳贡献、累计解释率
summary                 # 主导来源和诊断结论
```

### 7.4 密钥安全

- 高德 Key 和安全密钥不写入源码、JSON 或已跟踪文件。
- 本地通过被 Git 忽略的 `frontend/.env` 配置。
- 仓库仅提交不含真实值的 `.env.example`。
- 正式生产环境应由代理服务完成安全鉴权。

除密钥外，系统名称、数据根路径、高德版本与样式、地图中心点、诊断目标坐标、降级地图开关和 Act 1 自动节拍也统一通过环境变量配置，由 `frontend/src/config/runtime.ts` 集中读取。
