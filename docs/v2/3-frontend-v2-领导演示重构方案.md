# Frontend V2 领导演示重构方案

- 分支：`codex/20260729-200946-frontend-v2`
- 剧本基线：`docs/v2/1-剧本.md`
- 页面要求基线：`docs/v2/2-act.md`
- 演示对象：领导讲解、操作人员按稿顺序配合翻页

## 一、重构判断

旧版以六个技术 Act 为导航，每个 Act 内还有多个研判步骤。专业内容完整，但领导讲稿中的一句话往往需要操作人员跨页面、跨步骤寻找证据，容易出现三个问题：

1. 开场先看到技术流程，无法先回答“智能体依靠什么知识、平时在做什么”；
2. 同一讲稿段落分散在多个旧 Act，例如案例检索、方案生成、方案对比分属不同页面；
3. 页面强调过程步骤，领导最需要的结论、关键数字与下一句话不够稳定。

V2 改为两层叙事：

```text
常态扫描首页
  └─ 点击代表性“已完成”任务
      └─ 多源感知 → 智能研判 → 方案生成 → 落地执行 → 效果优化 → 持续优化
```

首页说明“知识底座 + 常态运行”；闭环页面说明“一个问题如何被自主解决”。页面顺序与讲稿顺序完全一致。

## 三、首页呈现逻辑

### 1. 左侧任务中心

- “正在执行”持续显示全市多源扫描；
- “已完成”保留代表性任务，整卡可点击；
- 代表任务在进入详情前即展示 `129m → 78m`，先给结果、再看过程；
- 保留异常数量与闭环完成率，说明智能体处于真实持续运行状态。

### 2. 中央地图

- 地图保持第一视觉中心，扫描光束与路口点位持续运行；
- 只放一条轻量扫描状态，不使用大面积面板遮挡路网；
- 底部保留主动任务输入框，说明系统同时支持自主发现和人工发起。

### 3. 右侧知识库

- 首屏直接展示讲稿中的七组知识资产数字；
- 数字卡可点击，详情以环形进度与一句解释呈现；
- 默认双 Tab：经验库、案例库；
- 经验库包含认知经验、治理经验、方案经验；
- 案例库包含行业案例、路口治理案例；
- 首页知识内容解释“这些知识具体是什么”，避免只报数字。

## 四、六段闭环的内容合并

### 01 多源感知

合并旧版“路口认知 + 异常核验”。页面同时展示目标路口、感知来源、设备覆盖、实时指标和动态阈值，结论固定为“异常真实且持续”。

### 02 智能研判

合并“拓扑分析 + 流量溯源 + 问题验证”。地图呈现上游—目标—下游关系，面板只保留完整因果链和被排除的假设。

### 03 方案生成

合并“案例检索 + 专家规则 + 专业模型测算 + 多方案对比”。先说明依据从哪里来，再说明模型在十几秒内生成什么。

### 04 落地执行

合并“方案影响评估 + 安全边界 + 信号机下发”。页面必须同时回答“为什么选它、下发了什么、越界怎么办”。

### 05 效果优化

合并“执行前后对比 + 晚高峰逐周期验证”。以 `129m → 78m` 为第一数字，并同时证明东西向和下游没有越界。

### 06 持续优化

复用日报与复盘逻辑，压缩为城市治理 KPI、经验沉淀流水线和本次新增代表经验，完成从单路口返回全市治理的收口。

## 五、可视化与操作约束

1. 领导视图的文字结构固定为：阶段名称、一句话结论、3—4个关键数字；
2. 业务空间关系始终由地图表达，左右面板只提供依据；
3. 顶部六段导航允许现场跳转，底部“上一阶段/下一阶段”用于顺序演示；
4. 底部讲解提示严格对应剧本段落，操作人员不需要记忆旧 Act 内部步骤；
5. 颜色语义固定：红色为已成立问题，橙色为成因或风险，蓝色为计算与动作，绿色为安全、完成和改善；
6. 1920×1080 为主演示尺寸，1366×768 下保持导航、关键数字和翻页控制可用。

## 六、验收顺序

1. 首页能否在不翻页的情况下讲完知识库数字；
2. 点击“已完成”是否进入多源感知第一页；
3. 连续点击六次是否与讲稿自然同步且无跨页回找；
4. 每一页遮住左右面板后，地图能否表达问题、动作或结果；
5. 所有阶段能否通过顶部导航直接回到指定段落；
6. 最后一页能否返回首页，形成“持续扫描”的闭环。
